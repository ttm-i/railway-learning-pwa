# 受入条件と最低限のテスト

## 鉄道データ
- [ ] データの権利台帳に再配布・加工・オフライン保存の確認結果がある。
- [ ] 同一駅IDの重複、参照切れ、不正な路線接続、駅順/分岐の破綻を検出できる。
- [ ] 公式ソースに未確認の接続を0乗換の直通と推測しない。
- [ ] 更新失敗で直前正常データを失わず、更新中のゲーム判定が変化しない。

## 地図・UI
- [ ] iPhoneでズーム・パン・駅タップ・ボトムシート展開が競合しない。
- [ ] 密集駅のタップ候補が識別可能で、候補の番号は地図/一覧で一致。
- [ ] 駅名・路線名を隠したゲームで、エラー・履歴・通過駅・候補一覧から答えが漏れない。
- [ ] 表示最適化後もゲーム内の経路および選択操作が失われない。
- [ ] 手動パン後は自動追従停止し、ボタン押下で現在駅へ復帰（GPSとは無関係）。

## クイズ
- [ ] 3形式を切替・組合せでき、テキストの妥当な表記ゆれを受理。
- [ ] 途中中断/復帰で未回答を不正解にしない。
- [ ] 手動チェックと自動習熟の値が混ざらない。
- [ ] 誤答即時再挑戦は間隔学習の実績と区別。

## ゲーム/経路検索
- [ ] 正当な隣接接続をたどり目的地に達し「この経路で確定」でのみ採点。
- [ ] 同駅再訪可だが過大ループへの安全対策あり。通過のみでは経由駅達成にならない。
- [ ] 別列車各停→急行=乗換1、確認済み同一列車種別変更=0、確認済み直通=0。
- [ ] 急行で中間3駅を通過した場合、駅間数は4、通過駅を訪問として加算しない。
- [ ] 徒歩のみ=列車乗換0、徒歩1。列車→徒歩→別列車=乗換1・徒歩1。
- [ ] 乗換最少と駅間最少は同じ経由駅/除外条件を満たす。重複結果は重複表示しない。
- [ ] 経路一覧の地点タップは閲覧のみ。「組み直す」でのみ切詰め。Redoはない。
- [ ] 無効な接続を押しても経路・成績を変更しない。
- [ ] クイズ・ゲームの一時保存が再起動後に復元できる。
- [ ] 最新データを導入しても過去の確定成績は変わらない。

## バックアップ/運用
- [x] JSON置き換え前に検証・プレビューと復元前スナップショット作成。
- [x] JSON統合前に検証・プレビューと、削除済み記録を復活させない競合処理。
- [ ] 読込失敗・容量不足でも既存データを維持。
- [x] 同じJSONの二重取込でUUID付き履歴が増殖しない。
- [ ] 安定版とテスト版が相互の記録を書き換えない。
- [x] 初回キャッシュ準備後、通信なしでMVP主要機能が動く。（2026-10-27 iPhone実機確認）
