# 鉄道ネットワークと評価（共通規範）

## 1 基本グラフ
- `station`（物理駅/駅施設の固有ID）、`line`（営業路線ID）、`line_station`（路線内の駅順）、`rail_edge`（連続する駅間）、`transfer_edge`（構内での乗換）、`walk_edge`（別駅間徒歩）、`service_pattern`（停車パターン）を区別。
- 経路状態に駅ID、現在利用路線、列車/サービス継続状態、必須経由駅の達成順を保持する。駅だけで状態を代表させない。
- 接続は `confirmed | unverified | impossible`。`unverified` は可否不明であり、可として計算しない。未登録の接続は `impossible` と断言しない。
- 直通運転・同一列車継続は、検証済みの情報があるケースのみ0乗換と判定。実在する全ダイヤの接続可能性は保証しない。
- 駅間を飛ばす急行移動は、既知の停車パターンの合法な停車駅間に限る。途中の駅間数はすべて積算し、通過駅は停車済扱いにしない。
- 指定経由駅は指定順に**停車/到達**して満たす。通過だけでは達成しない。
- 事業者/路線/徒歩接続除外は計算時のグラフ制約であり、元の路線図を削除しない。制約変更後は経路の有効性を再チェック。

## 2 指標（異なる指標を混ぜない）
- **列車乗換回数**: それまで乗車中の列車から、別の列車へ乗り継いだ回数。確認済み直通/同一列車種別変更は0。未確認は0と推測禁止。
- **鉄道駅間移動数**: 電車で通った隣接駅間数。急行で通過した区間もすべて加算。徒歩辺は加算しない。
- **徒歩接続回数**: 異なる駅間の徒歩辺を利用した回数。構内乗換とは別。
- **再訪回数**: 実際に再び到着/停車した駅の訪問回数から初回を除いた数。単なる急行通過は訪問としない。
- 正誤: 有効な接続のみで経路を作り、最後に目的駅に到着し、指定した経由駅を順序どおり達成すること。到着通知だけで採点確定せず、本人が「この経路で確定」を押す。
- 最適経路: **乗換最少**と**鉄道駅間移動数最少**を同じ制約で独立探索。重複する同一路径は一つにする。所要時間最少・運賃最少は主張しない。
- 主目的が同数の候補の採用順など、UIで『唯一の最適』と断定しないためのタイブレーク方針は `open-issues.md` に記載。

## 3 グラフ探索上の不変条件
1. 表示範囲外の駅も経路対象。
2. 無効/不明な接続の選択は経路データを変更しない。
3. 列車種別を変更しただけで即1乗換と断定しない。
4. 同じ駅の再訪可（無限ループ防止の計算上の上限は設ける）。
5. 経由駅/除外条件変更時は、構築済み経路の有効な先頭部分を保持し、無効部分の編集/切詰め/再開始を選べる。出発駅変更は通常リセット。
6. 計算に使うデータ版はプレイ中固定する。正答・結果履歴は確定時の版と紐づけて保存。
