# Codexに最初に送るメッセージ（そのままコピー可能）

このリポジトリで、**首都圏鉄道学習PWA**を段階的に開発してください。私はiPhoneからGitHub経由で確認します。最初は第1段階（地図・基本クイズ・基本経路ゲーム）の実装を目指します。無料運用・オフライン動作・既存データ保全を必須とします。

**必ず以下の順番で進めてください。**
1. `docs/README.md`, `docs/requirements.md`, `docs/data-model.md`, `docs/rail-graph.md`, `docs/map.md`, `docs/quiz.md`, `docs/route-game.md`, `docs/route-search.md`, `docs/ui.md`, `docs/offline-and-backup.md`, `docs/testing.md`, `docs/open-issues.md`, `docs/decision-log.md` を読んでください。正式仕様を優先し、決定履歴は参照用です。
2. 初めに現在のリポジトリを確認し、必要なファイル構成とMVP実装計画を明示してください。未確定事項は推測で決めず、`docs/open-issues.md` に仮説と検証事項を追記してください。
3. 鉄道データの利用条件が未確認なら、許諾を推定して実データをリポジトリに転載・配布しないでください。まずは**架空の小規模テスト路線網**を作り、描画・駅間探索・保存・クイズのE2Eを検証してください。実在路線を完成したかのように見せないでください。
4. 駅/路線/接続の安定ID、経路計算グラフと地図描画の分離、暗記モードの情報漏れ防止、乗換/通過駅/徒歩の指標分離、Redoなし、安全なデータ復元を守ってください。
5. ステップ単位で実装し、各ステップごとに変更ファイル、テスト結果、iPhoneでの確認方法、次の作業を報告してください。実行可能なテストは実行し、未実行なら理由を明示してください。
6. まず第1段階の最小機能とローカル動作確認手順を完成させてください。安定版とテスト版は保存領域の混線を防いでください。

なお、アプリを実装したと装うこと、未知の運行情報を創作すること、未確認のAPI・配布権を前提にすることは禁止します。
