# オフライン・データ更新・バックアップ

## オフライン
- 初回オンライン取得時にアプリ資産と必要鉄道データをキャッシュし、準備完了をチェックして表示。
- 地図/クイズ/経路検索/ゲーム/学習履歴/分析は保存済みデータによりオフライン動作。出典外部サイト閲覧と新データ取得はオンライン専用。
- Service Worker/Cache API/IndexedDB等を利用可能だが特定ライブラリや構成は固定しない。iOSのストレージ破棄・容量制限を想定し、失敗時には復旧案内を出す。
- 更新は起動時にオンラインなら確認。検証成功時のみ適用し、進行中セッションの鉄道データ版は固定。中断セッションも互換性を検証する。
- 過去結果を再採点しない。任意の最新版検証結果は別項目に保持。
- 変更履歴はバージョン・日付・出典・内容を表示。更新失敗時は正常な旧データを維持。

## JSONバックアップと復元
- 手動エクスポート。前回の書き出し操作から30日以上かつ新しい記録が10件以上の場合だけ、学習中を避けて設定画面内で控えめに案内。
- インポート時は形式検証→件数と対象のプレビュー→既存データの復旧用スナップショット確保→『置き換え』または『統合』選択→原子的な保存・検証→確定。
- 第1段階は安全な『置き換え』のみ提供する。置き換え直前の端末データを内部へ退避し、復元後に元へ戻せる。全データを一括処理し、途中で失敗した場合は変更前の状態を維持する。
- 『統合』は新形式のバックアップだけで利用可能。駅の習得状態は更新日時が新しい方、同一IDのクイズ回答・経路履歴・お気に入りは現在端末側を採用し、重複させない。現在端末の設定と進行中状態は維持する。
- 経路履歴とお気に入りの削除時は削除情報を残してバックアップへ含め、別端末や古いファイルから復活することを防ぐ。従来形式は削除情報がないため置き換え専用とする。
- 保存失敗時は元に戻し、置き換え直前の状態への復旧導線を用意。
- 統合は単なる配列結合禁止。UUID付き履歴は重複排除、習得状態は更新時刻だけでなく明示削除・競合を配慮した種別別ルールを適用。
- 端末内スナップショットは端末データ消失に対する外部バックアップの代わりではない。
