# 未解決課題・開発開始前のゲート

このファイルは決定済み110項目を勝手に上書きしないための課題管理票。`[BLOCK]`は該当機能の本実装までに回答/根拠が必要、`[SPIKE]`は小規模な技術実証で解消。

1. **[BLOCK/運行] 静的サービスと実列車乗継の表現**: 公式に確認できる『同一列車継続』『別列車乗継』『未確認』の3状態をモデル化。全ダイヤの運行再現や任意時刻での可否を保証しない。運行パターンの出典・適用期間を保存。
2. **[BLOCK/最適化] 同点経路の決定順**: 主目的が同じ複数経路を何で並べるか。暫定は駅間数/乗換数/徒歩数/安定IDの辞書式、ただし利用者への『唯一最適』断言禁止。正式決定とテストが必要。
3. **[BLOCK/権利] 出典別ライセンス台帳**: 国交省鉄道データ等について、商用の有無によらず再利用、地図画像/形状生成、改変、帰属表示、オフライン配布の要件を実際に確認。資料を見ただけで利用許諾があるとみなさない。
4. **[BLOCK/更新] 中断時の旧鉄道データ版**: 旧版を保管し復帰させる容量/寿命規則、旧版欠損時の安全な案内、保存済みの進捗の不変条件を設計。
5. **[BLOCK/統合] JSON競合処理**: 手動習得フラグの解除、削除済み履歴、複数端末間の競合、同一UUIDの相違についての種類別ルール。削除トゥームストーンの範囲を決める。
6. **[BLOCK/評価] 再訪の判定対象**: 停車・徒歩到着を再訪として数え、通過は数えない暫定仕様。駅構内の乗換だけの場合の再訪扱いを明文化。
7. **[BLOCK/初期データ] MVPで提供可能な駅・路線・接続のカバー率**: 対象3地域の完全性を保証する前に、必須データの充足率と欠落表示を検証。未確認の直通・急行を創作しない。
8. **[SPIKE/地図] Canvas/SVG/WebGL描画技術**: iPhone実機でFPS/パン遅延/ラベル重なり/アクセシビリティを比較して決定。
9. **[SPIKE/PWA] iOSのオフライン容量と更新競合**: ホーム画面PWAとSafariで保存/キャッシュ更新/強制終了/再開/端末空き容量不足を検証。
10. **[SPIKE/ホスト] 無料ホスティングと安定版・試験版の分離**: GitHub Pages等の利用規約、オリジン別のキャッシュ境界、カスタムドメインの要否、更新頻度の制限を実際に確認。

## 確定済みの矛盾解消
- Q53でRedoなし。以前のQ85の文中にあった『取り消しを元に戻せる』示唆は不採用。Q104のバックアップ復元は別の機能。
- Q93の徒歩接続は独立カウントであり『駅間移動最少』の鉄道駅間数には徒歩を足さない。ただし徒歩無料の最適化で歩行ばかりの経路を過度に優遇する恐れがあり、今後の比較UIで『徒歩回数』を同時表示。
- Q95『未確認』と『未登録』と『確認済み不可』を区別。未知の移動を成功扱いしない。

## 安全な開発の開始条件
第1段階では、全運行パターンが揃うまで待つ必要はない。**出典確認済みの限定路線網**で地図・クイズ・駅単位ゲームを先行実装してテストし、未確認の第2段階機能を未実装表示とする。後から第2段階で運行判定を拡張しても、学習履歴を壊さない。

## 2026-10-26 開発着手時の仮説と検証予定

- `[SPIKE/地図]` 第1段階の架空小規模網は、駅をキーボードでも選べるSVGで試作する。これは最終技術の決定ではない。iPhone実機で操作性と描画速度を確認し、Canvas/WebGLとの比較要否を判断する。

- `[SPIKE/ホスト]` 最初はGitHub Pagesの安定版だけを自動公開する。試験版の別URLは、Pagesの構成と保存領域の分離を確認してから追加する。
- `[BLOCK/権利]` 実在データは未投入。自作の架空データだけで地図、探索、保存、クイズの流れを検証する。
